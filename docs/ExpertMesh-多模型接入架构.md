# ExpertMesh 多模型接入架构

日期：2026-10-09。目标架构。v0.1 已实现多协议流式输出、工具续接、加密凭证与配置快照，尚未进行各厂商真实账号验证。当前使用本地 SQLite 和单进程运行时，详细实现边界见 [开发与适配器](开发与适配器.md)。技术说明集中在架构文档，产品界面呈现操作与结果。

## 接入与身份

UI → 应用服务 → Agent Runtime → Model Gateway → Provider Adapter。工具、知识、助手身份与记忆不耦合厂商 SDK。稳定 assistant_id 关联指令、项目、权限与记忆；provider/model 是运行配置。

| 类型 | 目标服务 | 要求 |
| --- | --- | --- |
| 专用协议 | OpenAI、Anthropic、Google Gemini | 独立适配消息、工具、流式事件、用量与错误 |
| 兼容接口 | DeepSeek、百炼/Qwen、智谱/GLM、自定义地址 | 每家验证兼容范围，不假设全部能力相同 |
| 本地服务 | Ollama；兼容入口可扩展 LM Studio/vLLM | 发现模型，验证工具、图片等能力 |
| 聚合网关 | OpenRouter 等 | 明确服务路由和数据目的地 |

可以评估 LiteLLM 作为网关实现，但保留项目自己的契约与验证层。目录仅供参考，不能替代测试：[LiteLLM Providers](https://docs.litellm.ai/docs/providers)。模型 ID 按当前接口发现或手动配置。

## 数据契约

Connection：id/provider/name/base_url/credential_ref/enabled。Model：id/connection_id/provider_model_id/display_name/capabilities/limits。RunConfig 保存模型、参数、工具、预算和配置版本。

统一请求包含消息、附件引用、工具定义、输出约束和取消信号。统一事件包含文本增量、工具调用增量、结束原因、用量与错误。隐藏推理不作为用户可审计证据。

能力分别记录文本、图片、工具调用、流式工具、结构化输出、并行工具、上下文限制与验证时间。模型发现失败允许手动添加。静态注册不代表实时可用。

## 运行与恢复

任务启动保存模型与连接快照，助手身份和记忆引用独立持久化。模型更换在请求或工具完成的安全边界生效。保存标准化消息与事件，恢复不得重复执行有副作用的工具。

区分限流、超时、认证错误、上下文超限与能力不匹配。重试有上限和退避。不同供应商之间的自动回退须用户预先启用，不静默跨厂商发送资料。并发助手共享任务预算并遵循供应商限额。

## 凭证与工具

密钥存储在服务端环境变量或安全凭证库，仅返回遮挡信息及引用。前端、聊天、日志、追踪、导出和 widgetState 不保存密钥。连接测试由后端执行；自定义地址限制访问范围，局域网服务通过明确配置放行。

模型 API、搜索、MCP、代码执行和文件目录分别配置。任务记录实际模型与工具。文件权限按项目范围执行，发布、删除和外发操作按授权策略处理。个人偏好、项目知识和助手私有记忆遵循既有隔离与来源规则。

## 适配器验证与开源扩展

每个适配器验证普通/流式回答、连续工具调用、附件、结构化输出、取消、错误、用量、超限与恢复。能力不存在时明确降级或选择其他模型，不伪造工具成功。

提供适配器接口、配置示例与契约测试，支持矩阵只记录通过验证的组合。开源部署提供 Docker Compose、环境变量样例与迁移说明，商业托管不作为启动依赖。
