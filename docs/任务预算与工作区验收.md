# 任务预算与本地工作区验收

使用 http://127.0.0.1:3001 进行本地验收。需要配置一个支持工具调用的模型；线上模型与权限使用你自己的供应商账号。

## 1. 预算暂停与恢复

1. 打开“设置 → 执行与工作区”，将模型调用次数设为 1，保存默认预算。
2. 新建任务：“请先读取资料，再生成一份摘要。”上传文本资料，确保模型实际使用工具。
3. 首轮模型调用完成后，需要继续调用时任务应暂停，卡片显示预算原因。
4. 展开“任务预算”，调整模型调用次数为 24，保存后点击“继续”。累计调用从原值增加，不归零；已完成工具结果按检查点复用。
5. 结束后把默认预算恢复为 24。已有任务的预算不会随默认设置变化。

## 2. 记忆版本追踪

1. 为通用助手保存一条明确偏好，例如“回答先给结论”。
2. 执行任务，展开“执行记录 → 已提供记忆”，确认出现内容、版本与来源。
3. 在助手设置中更正这条记忆，填写原因后再发起任务。
4. 新任务显示新版本，旧任务仍保留原版本；撤销后后续上下文不再提供它。这个记录表示提供信息，不能证明模型实际采用。

## 3. 只读工作区

1. 连接本项目下的 `examples/acceptance-workspace`，名称填写“验收项目”。
2. 在通用助手、个人空间下勾选“允许读取”，点击“查看文件”，应看到 `README.md` 和 `calculate.py`。
3. 发起任务：“读取验收项目中的 calculate.py，说明它计算的结果，并给出文件依据。”
4. 其他未授权助手不能读取该目录。撤销授权后，新的读取应被拒绝；“移除连接”只移除登记，不删除磁盘文件。

## 4. 真实代码执行

1. 启动本机 Docker，使用 Linux 容器引擎。
2. 设置中点击“准备并检查环境”，完成后开启“允许助手运行代码”。
3. 点击“测试 Python”和“测试 JavaScript”，应显示“代码执行正常”及退出码 0。
4. 新建任务：“读取验收项目的 calculate.py，在 Python 沙箱中执行它，再执行 assert calculate_total([12, 18, 6]) == 36，展示真实执行结果。”
5. 展开“代码执行结果”，检查输出、退出码与快照文件数量；文件不会被写回原项目。
6. 可另发任务要求运行 `raise ValueError('验收错误')`，应记录非零退出码；死循环应在设置的时限内中断，不显示成功。

执行时不能联网安装依赖，临时目录里的文件不保留。模型可能选择分析而不调用工具，应明确要求使用工具，并检查实际记录。
