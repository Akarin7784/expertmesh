# v0.1 实现与扩展

## 代码路径

- `server/app.ts`：本地单用户 API、输入校验、上传、连接与数据管理。
- `server/db.ts`：内置 SQLite/WAL。当前每个实体以 JSON 行存储，后续可迁移到关系化表和 PostgreSQL。
- `server/security.ts`：凭证加密、地址校验、固定 DNS、关闭重定向。
- `server/providers.ts`：原生协议与统一 Turn。
- `server/runtime.ts`：主/子任务、工具循环、检查点、取消与恢复。
- `src/App.tsx`：产品页面及设置、项目、助手表单；`src/styles.css` 负责响应式与主题。

## 新增供应商

兼容 Chat Completions 的服务可使用“自定义兼容服务”，不必修改代码。独立协议需要在 shared Provider 联合类型和供应商入口中注册，并实现：

1. `firstHistory`：统一文本消息转换成原生历史。
2. `generate`：流式输出、工具调用、完整的原生续接历史和明确结束标识。
3. `toolResult`：保留工具 ID、签名或其它厂商需要的关联信息。
4. `discover`：有支持时获取模型列表，失败允许手动配置。

Turn 的 `text` 只包含面向用户的文本，`calls` 包含工具请求，`history` 包含续接所需原生内容。原生历史只留在后端，不通过任务 API 返回。停止、断流或输出超限不能被当成成功。

参考本次核对的官方接口：[OpenAI 流式响应](https://developers.openai.com/api/docs/guides/streaming-responses)、[OpenAI 函数调用](https://developers.openai.com/api/docs/guides/function-calling)、[Anthropic Messages 流式事件](https://platform.claude.com/docs/en/build-with-claude/streaming)、[Gemini 内容生成](https://ai.google.dev/api/generate-content)、[Gemini 函数调用](https://ai.google.dev/gemini-api/docs/function-calling)、[Ollama Chat](https://docs.ollama.com/api/chat)。模型能力变化需要对实际配置再验证。

## 恢复语义

检查点保存原生消息、待处理工具调用、已处理游标和轮次。工具结果按 task_id + call_id 缓存，生成文件按固定 ID 保存；重启后可复用这些结果。子任务 ID 也从父任务与委派调用确定，已完成子任务不重复执行。

未完成的模型流不会作为完整历史保存。暂停会取消在途请求，继续时重做这一模型轮次，可能再次产生模型费用；不保证从一个字符精确续接。已完成的工具操作和文件仍保留。当前没有自动网络重试、租约或多进程 worker，不支持多个服务进程共享数据目录。

助手偏好由用户明确保存、按 assistant_id + project_id 隔离，注入有长度与数量上限。这是可控的显式记忆，不是自动学习或研究方案的完整记忆治理系统。

## 后续工作

当前优先扩展模型真实账号验证、资料类型与受限工具接入，再增加工作目录、代码执行、MCP 与自动记忆治理。引入副作用工具前，需要审批策略、幂等键与恢复核对。远程多人部署需要先做认证、授权、关系化数据迁移与并发调度。
