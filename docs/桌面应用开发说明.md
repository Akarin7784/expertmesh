# 桌面应用开发与验收

开发日期：2026-10-10。首版沿用 React 界面、Express API、SQLite、模型适配与任务运行时，通过 Electron 提供独立窗口与原生目录选择。

## 结构与运行

- `desktop/main.ts`：单实例、窗口、后端生命周期、目录选择、外链与窗口权限。
- `desktop/backend.ts`：Electron utility process 内启动现有服务，监听 `127.0.0.1` 的随机端口，收到关闭消息后暂停任务、释放连接并关闭数据库。
- `desktop/preload.ts`：仅暴露目录选择、窗口操作及窗口状态订阅，不向页面暴露文件读取、命令执行或通用 IPC。
- `src/WindowControls.tsx`：在页面顶部提供最小化、最大化/还原、关闭按钮，随系统窗口状态更新。
- `desktop/build.mjs`：将主进程、preload 和后端分别打包成 CommonJS，复制生产前端并生成独立应用清单。依赖随代码打包，不要求用户安装 Node.js。
- `electron-builder.json`：Windows NSIS、macOS DMG、Linux AppImage 配置；输出到忽略的 `release/`。

桌面启动使用生产构建，`npm run desktop` 每次会重建，不提供热更新。已有 Web 入口和 Docker 部署保留。Electron 运行时由 `npm run desktop:runtime` 显式安装，便于只开发 Web 的用户按需下载。

## 本地访问与权限

主进程生成每次启动的新会话令牌，仅向本应用地址的网络请求添加请求头。后端验证令牌，普通浏览器无法访问桌面 API 与静态页面。页面脚本不接收令牌；请求 Origin 使用实际监听端口验证。桌面不读取项目 `.env`，使用用户目录保存数据库及加密主密钥。

窗口启用 sandbox、contextIsolation、webSecurity，关闭 Node 集成、webview 和新增窗口；权限请求统一拒绝。应用内导航限制为本服务 origin，HTTP(S) 外链交给默认浏览器，拒绝文件和系统协议链接。目录和窗口操作 IPC 校验当前窗口及主 frame，取消目录选择返回 null。选择目录仅填写路径，助手访问仍由已有工作区授权控制。

桌面隐藏系统标题栏，Windows/Linux 移除菜单栏；窗口按钮融入应用顶部，颜色跟随界面主题。保留原生阴影与窗口边缘缩放，Windows 禁用系统强调色边框；系统支持时使用原生圆角（Windows 11 及以上）。界面以细描边区分窗口边缘，失去焦点时淡化，最大化或全屏时隐藏。顶部留白和品牌区用于拖动，按钮排除拖动区域。页面在独立内容区滚动，所有桌面滚动条隐藏，滚轮、触控板和键盘滚动仍可使用；顶部按钮保持可见。

设置页的标题、目录和章节内容分开布局；目录与内容各自滚动，滚轮不会带动另一栏。窄窗口把目录放在内容上方，依然独立滚动。切换章节时内容回到顶部，已经填写但尚未保存的表单保留。桌面验收覆盖 1320×900、1100×650、720×540 三种窗口尺寸。

桌面使用独立且不持久化的浏览器 session。主题等 localStorage 界面偏好在关闭后不会保留，后端保存的预算、授权、连接、对话及任务仍会保留。后续可单独设计持久化的界面偏好。

测试可使用 `EXPERTMESH_DESKTOP_DATA_DIR` 指定临时数据库目录，`EXPERTMESH_DESKTOP_USER_DATA_DIR` 隔离浏览器配置与单实例锁；`EXPERTMESH_DESKTOP_EXECUTABLE` 可指定打包后的可执行文件。普通用户无需设置这些变量。

## 验收

```sh
npm run check
npm test
npm run test:e2e
npm run test:desktop
npm run desktop:pack
```

桌面测试真实启动 Electron 和随包后端，使用临时数据目录验证：

1. 首页加载成功，渲染器没有 `require`，沙箱与上下文隔离开启。
2. 普通 HTTP 客户端被后端拒绝，桌面窗口正常请求。
3. 目录选择按钮经过真实 preload/IPC；仅替换系统对话框返回值，验证选择和取消。目录连接后需要明确授权才可列出文件。
4. 设置保存与导出下载完成，重启保留预算及工作区。
5. 应用关闭后服务端口不可访问，数据库和主密钥保留。
6. 顶部按钮实际最小化、最大化、还原和关闭窗口；系统窗口状态变化同步到按钮。深浅主题下滚动内容后，按钮仍固定在顶部，滚动条不显示。
7. 最大化隐藏界面描边，还原重新显示；模拟主进程 focus/blur 事件验证描边淡化及恢复，窗口开启阴影及缩放。Windows 自动化环境可能保持焦点模拟，测试不据此断言系统真实焦点转移；自动化未操作原生边缘拖拽，边缘缩放由 Windows 的 thickFrame 提供。

自动化不会展示和操作真实系统目录/保存对话框；它覆盖 IPC 和下载完成路径。第三方付费模型、真实 Docker 执行与 macOS/Linux 仍需在对应环境验收。Windows CI 会测试源码启动与打包后的可执行文件，并保存免安装目录作为构建产物。

本机验收结果：类型检查、格式检查、生产构建通过；后端测试 23 项通过、1 项真实 Docker 测试按默认配置跳过；Web 浏览器测试 8 项通过；Electron 源码启动与 Windows x64 打包后启动各通过 1 项完整集成测试。打包后的 `app.asar` 不含 `node_modules`，不依赖外部 Node.js。NSIS 安装流程、签名与自动更新尚未验收。

无边框版本补充验收：深浅主题、顶部按钮状态同步、真实最小化/最大化/还原/关闭，以及隐藏滚动条后的滚轮、PageDown/Home 滚动。Web 回归中首次有一项超出 30 秒总时限，一项因桌面测试清理共用目录丢失 trace；已隔离桌面测试输出目录，随后将失败的两项以 60 秒时限重跑通过。

## 后续开发

优先补齐应用图标、窗口与界面偏好持久化、已有 Web 数据迁移入口，再加入签名安装包、版本更新和崩溃日志。系统托盘、开机启动和全局快捷键需要结合明确的后台任务体验设计。宿主机写入和电脑控制仍需独立权限及恢复设计。

参考：[Electron utilityProcess](https://www.electronjs.org/docs/latest/api/utility-process)、[安全建议](https://www.electronjs.org/docs/latest/tutorial/security/)。
