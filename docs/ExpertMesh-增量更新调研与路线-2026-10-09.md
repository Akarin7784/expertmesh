# ExpertMesh 增量更新调研与路线

调研日期：2026-10-09（北京时间）。近期资料窗口：2026-09-09 至 2026-10-09。本文基于当前实现提出下一阶段建议，不代表新增功能已经开发。论文核对了摘要和提交日期，厂商资料阅读了发布说明；未复现论文实验、未部署外部沙箱，也未把原型协议测试当作真实模型效果评测。

## 当前基础与缺口

已完成：多供应商模型、搜索与网页来源、协作契约及逐项验收、执行记录、检查点恢复、独立助手与项目记忆、来源校验、候选确认、版本更正、撤销和失效处理、自定义主题下拉框。

当前验证包括 17 项后端/协议测试及 2 项浏览器回归，使用本地协议测试服务。它们证明流程、权限和数据状态符合预期，尚不证明真实模型能准确提取记忆、服从纠错或从多助手协作中获得收益。主助手验收仍是模型自身判断，尚无独立验证器。记忆检索仍是关键词，尚无使用情况追踪、语义冲突关联或项目共享发布；暂无 MCP、代码执行和工作区挂载。

## 建议的增量顺序

以下优先级是结合现有代码作出的产品与工程判断，不是上述论文共同证明的最优顺序。

| 顺序 | 用户能感知的增量 | 最小实施范围 | 完成与验收条件 |
| --- | --- | --- | --- |
| 1 | 知道记忆是否帮上忙 | 每次模型调用记录实际提供的记忆 ID、版本和提供方式；工具召回另记。已提供、模型引用、独立核验三个状态分开 | 更正前后的版本可追溯；无记忆/有效记忆/旧记忆对照评测有结果，不能把“注入提示词”显示成“已经采用” |
| 2 | 助手可以使用外部资料工具 | 只读 MCP 客户端：连接、测试、工具列表、逐助手授权、超时/取消、输出限额。首批仅支持经过验证的 HTTP 传输；stdio 另一个增量 | 未授权工具不会进入模型列表，调用时再次检查；同名工具不冲突；超时、断连、错误结果可见；凭证不进入模型和导出 |
| 3 | 每次任务有明确用量上限 | 根任务与子任务共用模型调用、工具次数、搜索和上下文预算；剩余不足时给出已完成内容。费用预算仅在有可靠价格配置时启用 | 中断/恢复不重置预算，错误尝试也计入相应配额；token 未返回时保持未知，不能用于严格费用保证 |
| 4 | 可以连接本地项目资料 | 独立“工作区”：只读选定目录、文件检索、引用定位，产物写入独立输出目录；不默认写入原项目 | 路径与符号链接不能逃逸授权目录；多个工作区和助手范围隔离；文件变更触发相关记忆重新核对 |
| 5 | 可以运行代码和验证成果 | SandboxProvider 接口、固定镜像、资源上限、网络策略、只读输入、独立可写目录；任务/子任务各自记录执行环境与产物 | 通过隔离、路径、网络及中断恢复测试后才能启用；收集真实退出码与测试输出，不以模型自述替代验证 |
| 6 | 复杂任务可并行协作 | 在冻结契约基础上引入依赖 DAG，仅并行互不依赖的任务；队列取消、共享预算和主助手汇总；先维持最多三个子任务 | 与顺序执行及单助手在同模型、同输入、同预算下对比质量、时延和总调用；收益不足时不默认启用并行 |
| 7 | 团队助手共享经过确认的项目知识 | 从私有记忆显式发布项目记录，保存发布人、原始证据及继承关系；源版本变更触发共享记录失效或待复核 | 未发布的私有记录不被其他助手召回；撤销覆盖索引、共享视图和模型上下文；复制来源不增加证据数量 |

不把共享记忆与并行调度放在第一批：它们会扩大错误传播和协调成本。先有使用证据、调用预算和真实工具边界，再增加自主程度。

## 下一个主功能：只读 MCP

产品入口放在设置中的“工具连接”。填写地址后测试连接，查看可用工具，再为助手启用选定工具。聊天保持原有简洁布局，任务活动显示工具名称、进度和结果；详细调用记录继续折叠。协议版本、连接重试和鉴权细节进入开发文档或高级设置。

建议的数据与执行关系：

- ToolConnection：地址、传输、凭证引用、连接状态和经测试的版本。
- ToolGrant：助手/项目范围、允许的工具 ID、期限、读写策略。
- ToolDescriptor：连接内名称、输入/输出 Schema、描述哈希和能力快照；第三方描述作为不可信输入。
- ToolInvocation：参数摘要、授权版本、调用状态、时延、结果引用与错误，不采集原始密钥。

调用链为：发现工具 → 校验描述 → 用户授权 → 按任务筛选 → 运行时再次检查 → 调用 → 限制并解析返回 → 保存结果。不能只根据服务器声明的 readOnlyHint 放行：只读策略还需来自可信服务器范围和本地工具清单；实际外部行为不能仅凭 Schema 或工具名字证明。

恢复策略先保守处理：确定已成功且结果已落盘的调用复用结果；外部效果不明的调用标记为“需要检查”，不自动重发。未来写操作需要幂等键、结果核对或明确重试决策，检查点本身不能保证 exactly-once。

## 最小评测集

先建立版本化数据集与离线报告，不接收费模型自动跑 CI。需要真实模型时由开发者显式选择模型、预算和凭证。

1. 记忆：无记忆、正确记忆、已更正、撤销、来源删除、过期、冲突、复制证据；至少比较任务成功、错误事实采用、证据命中、用量与延迟。
2. 工具：越权、同名工具、畸形 Schema、超大输出、注入式返回、超时、取消、断连、调用后进程退出；确定性安全检查与模型行为评分分开报告。
3. 协作：单助手/顺序多助手/并行多助手；固定总预算，记录重复工作、验收通过率、整合错误与执行耗时。

**下一批建议交付：**先补记忆使用追踪和小规模评测夹具，同时开展只读 MCP 的接口设计；随后开发工具连接与授权闭环。工作区、沙箱、并行和项目共享各自作为后续可独立验收的增量。
